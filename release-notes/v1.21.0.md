# v1.21.0

## Changes

- **Codex guard subagent defaults updated to the new practice**: the built-in
  guard schema (`src-tauri/src/codex_guard/guard_schema.json`) now targets the
  current multi-agent configuration layout.
  - **Concurrency moves to the `[agents]` table**: the v2-table key
    `features.multi_agent_v2.max_concurrent_threads_per_session` (default 7)
    is replaced by `agents.enabled` (bool, default true) and
    `agents.max_concurrent_threads_per_session` (int, default 10 subagents,
    not counting the main agent).
  - **New key** `features.multi_agent_v2.expose_spawn_agent_model_overrides`
    (bool, default false): spawn_agent no longer exposes model /
    reasoning-effort overrides to the main agent.
  - **wait timeouts** now default to 50000 / 120000 / 240000 ms
    (min / default / max; previously 10000 / 30000 / 120000).
  - **"Remove legacy multi_agent_v1 keys"** reworded: since `[agents]` now
    carries valid keys, the entry's description makes clear only the v1 keys
    (max_threads / max_depth / interrupt_message) should go.
  - **AGENTS.md「子代理使用」block replaced** (zh/en): fork_turns="none" on
    every dispatch, suspend-and-wait after a concurrent batch, results via
    final replies (no report files), no nested subagents, and
    `agent_type = "default"` when the tool exposes it. Conflicting legacy
    rules (10-minute timeout, close_agent, single-use) are dropped.
  - **agents/default.toml replaced** (zh/en): reasoning effort low →
    `medium`; new developer instructions (first-line status
    complete/partial/blocked, exactly one FINAL_ANSWER, no report files, no
    nested spawning); adds `[agents] enabled = false` and
    `[features] image_generation = false` in the subagent config layer.

## Upgrade notes

- Existing installs whose on-disk schema copy
  (`~/.codex-pro-max/codex-guard-schema.json`) still holds the old entries
  keep those values per the disk-overrides-builtin merge rule; delete the
  stale entries in the guard UI (or sync the file) for the new defaults to
  take over. The three newly added entries have no disk counterpart and take
  effect immediately.
