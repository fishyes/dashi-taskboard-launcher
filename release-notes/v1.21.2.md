# v1.21.2

## Fixes

- **Config guard: stale on-disk schema copies no longer override the
  built-in defaults.** The guard used to merge
  `~/.codex-pro-max/codex-guard-schema.json` with "same-id disk overrides
  builtin; disk-only entries kept", and the first run released a full copy
  of the built-in schema to disk. Any copy written by an older version
  silently fossilized — and the UI offers no way to delete non-custom
  entries. On machines carrying a pre-v1.21.0 copy this caused the two
  regressions reported against v1.21.1:
  - **Conflicting locked params in the 60s poll loop**: the fossil
    `agents-v1-remove` (whole-`[agents]`-table removal) and the fossil
    `features.multi_agent_v2.max_concurrent_threads_per_session = 7` entry
    kept fighting the new locked entries (`agents.enabled`,
    `agents.max_concurrent_threads_per_session = 10`, and the per-key
    `toml_absent` cleanup entries) — each poll pass undid the other side.
  - **「子代理使用」section and `agents/default.toml` never updated**: the
    fossil entries' old `default` content (pre-v1.21.0 wording,
    `model_reasoning_effort = "low"`) overrode the new built-in texts, so
    locked params kept "restoring" the old content into `~/.codex`.
- **New merge rule**: the built-in schema is the single source of truth for
  built-in params (defaults and English resources included); the disk file
  carries only user-defined custom params (`custom = true`). Fossil entries
  (same-id copies of built-ins, or entries removed from the built-in set)
  are ignored on load, and the disk file is rewritten to the cleaned custom
  set when anything was dropped. First run now releases an empty custom
  list instead of a full built-in copy, so future upgrades cannot
  fossilize. Per-param applied/locked/value states in the launcher config
  are untouched; after upgrading, locked params heal `~/.codex` to the
  current defaults on the next poll (≤ 60 s while the launcher runs) — no
  manual schema-file cleanup needed anymore.

## Notes

- The previously managed `features.multi_agent_v2.enabled` and
  `features.multi_agent_v2.tool_namespace` keys are no longer written by
  the guard, but existing values in `~/.codex/config.toml` are left in
  place (both remain valid, no-op-adjacent keys in codex 0.153.2); delete
  them by hand if you want a fully clean table.
- Hand edits of built-in entries in the disk schema file (never supported
  by the UI) are dropped on load.
